# IFRS source and entity evidence connector

The opt-in `/rag/evidence` routes are separate from the legacy signal-writing RAG routes. They perform no PE/RE signal writes. Existing `/rag/query` and `/rag/retrieve` behavior is unchanged.

Configure `IFRS_EVIDENCE_TOKEN`, `IFRS_EVIDENCE_STATE_DIR` (persistent private storage outside Git) and `IFRS_EVIDENCE_BUNDLE` (operator-selected directory containing `ingestion-manifest.json`). Use existing Qdrant/embedding settings. The focused development entrypoint `scripts/ifrs-evidence-api.py` also supports `IFRS_QDRANT_PATH` for a persistent local Qdrant deployment. It does not establish composed-universe or native parity acceptance.

POST `/rag/evidence/reconcile` with the service Bearer credential. The request cannot choose a bundle path or destination collection. The manifest is the document allowlist; role-to-collection mapping is fixed. Files must match content hashes and edition, and remain inside the bundle's documents directory. Runtime machine/agent configuration and arbitrary upload metadata cannot reroute this ingestion. Private standard text is not committed here.

Three logical collections remain distinct: `ifrs_smes_2025_standard`, `ifrs_accounting_review`, `ifrs_document_workflows`. Existing model-aware aliases/dimension guards apply. An unchanged run performs no new embeddings. Changes/removals affect only manifest-owned points. A dirty reconciliation is unavailable to readers until complete; retries use stable point IDs and bounded eight-document embedding batches. No health/user collection is reconciled.

POST `/rag/evidence/retrieve` with domain, documentRole, edition, question, and optional documentId/sourceSHA256/sectionId/indexSnapshot. `method` is `semantic` or `exact-source`; exact-source requires a document ID and is labelled as such. Chunk boundaries retain paragraph/list context, exact character/line spans, source/content/text hashes and authority provenance. Paragraph labels in the supplied extraction remain explicitly unverified. Retrieval never promotes review prose into operative authority.

GET `/rag/evidence/receipts/{interactionId}` returns the immutable receipt. POST `/rag/evidence/query` generates a fresh advisory answer from that request's passages with the configured local model. Unsupported/malformed citations are unresolved. Valid IDs alone do not establish entailment or accounting correctness; raw model observations and the independent-review requirement remain visible. Model answers are never cached to make engines agree.

For actual entity projection, configure a private `IFRS_ENTITY_CONNECTOR_CONFIG` file with canonical sidecar URL, read-only projection credential, operator-pinned entity/period contexts and `evidenceClass: actual`. Synthetic testing uses a separate state directory and `evidenceClass: synthetic`. POST `/rag/evidence/entity/reconcile` pulls canonical heads; it accepts no caller-authored events. POST `/rag/evidence/entity/retrieve` requires entityId, period and assetTypeId; optional revision requests explicit historical evidence. Current-approved reads check the canonical head synchronously and fail closed on stale state, lag or unavailability. This projection is structured artifact retrieval, not a claim of semantic search over entity documents.

The canonical document sidecar remains the only head owner. Synthetic/actual evidence cannot share a projection. Revision events are monotonic and idempotent; a delayed event cannot resurrect an earlier approved head. Owner/reviewer names are business roles, not new identity infrastructure. The service token is an operator/service boundary; keep it out of model prompts and client logs.

Verification is owned by `RealityEngine_CI/scripts/verify-ifrs-workflows.py`. It records manifest census, real embedding/retrieval, source gaps, source receipts, synthetic case results, deployed lifecycle/projection, optional real gateway tool invocation and live model observations as distinct phases. Full IFRS admission and source-finding closure are separate gates.
